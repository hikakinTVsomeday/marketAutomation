# 答弁ウォッチ（プロトタイプ）

国会の質問主意書と政府答弁書をAIが読み、

1. **何を聞いているのか／どう答えたのかを平易な日本語に翻訳**し、
2. **答弁が質問に実質的に答えているか（誠実度）を逐条で評価**する

サイトの試作です。不誠実な「それっぽい答弁」を可視化して圧力にすると同時に、
具体的なデータ開示や立場の明言といった**誠実な対応もハイライト**して、
良い答弁が評価される構造をつくることを狙います。

サイトは「一覧 → 答弁の逐条評価 → 提出者／答弁者ページ」の3層構成で、
提出者・答弁者ごとに平均スコア・判定分布・頻出回避パターンを集計表示します。

## 構成

```
toben-watch/
├── scripts/
│   ├── fetch_syuisyo.py   # 参議院サイトから質問・答弁ペアを取得 → data/raw/
│   └── analyze.py         # Claude API で逐条評価 → data/analyses/
├── data/
│   ├── raw/               # 取得した原文（質問・答弁の全文＋メタ情報）
│   └── analyses/          # 解析結果（評価 JSON）
└── site/
    ├── template.html      # ページテンプレート（デザイン＋レンダラ）
    ├── build.py           # analyses を埋め込んで index.html を生成
    └── index.html         # 生成された静的デモページ
```

パイプラインは「取得 → 解析 → 静的サイト生成」の3段で、すべて JSON を介して疎結合です。

```bash
# 1. 取得（標準ライブラリのみで動く。参議院・衆議院両対応）
python3 scripts/fetch_syuisyo.py sangiin 214 14
python3 scripts/fetch_syuisyo.py shugiin 198 99

# 2. 解析（要 ANTHROPIC_API_KEY / pip install anthropic）
python3 scripts/analyze.py data/raw/sangiin-214-014.json

# 3. サイト生成
python3 site/build.py
```

※ 同梱の `data/analyses/sangiin-214-014.json` は、このリポジトリ作成時に
Claude が原文を読んで作成したサンプル解析です。`analyze.py` は同じスキーマの
JSON を API 経由で自動生成します（構造化出力を使用、モデルは claude-opus-5）。

## 評価の設計

### 逐条評価（設問ごと）

| 項目 | 内容 |
|---|---|
| verdict | `answered` 回答 / `partial` 部分回答 / `evaded` 実質回答なし / `refused_with_reason` 理由明示の回答拒否 |
| responsiveness | 0–100。質問への実質的な応答度 |
| patterns | 下記の回避パターン分類でタグ付け |
| good_point | 誠実な対応（データ開示・立場の明言など）を積極的に記録 |

### 回避パターン分類

| コード | 名称 | 典型表現 |
|---|---|---|
| P1 | 趣旨不明型 | 「お尋ねの趣旨が明らかではない」 |
| P2 | 差し控え型 | 「お答えを差し控えたい」 |
| P3 | 作業困難型 | 「膨大な作業を要する」 |
| P4 | 過去答弁引用型 | 「〜と答弁したとおりである」 |
| P5 | まとめ答弁型 | 「二、四及び六について」等の一括処理 |
| P6 | 指標すり替え型 | 問われた数値・定義と別のものに断りなく置換 |
| P7 | 仮定不応答型 | 「仮定の質問にはお答えできない」 |
| P8 | 論点スルー型 | 質問者の論拠に反論せず結論のみ述べる |
| P9 | 一概困難型 | 「個別具体の事情により一概にお答えすることは困難」 |

定型句ベースなので、P1〜P3・P5 あたりは将来的に**ルールベース検出＋AI判定の
二段構え**にでき、集計（「今国会の趣旨不明型は◯件」「省庁別ランキング」）が機械的に出せます。

### 中立性の担保

- 評価対象は「質問に答えているか」という**応答の質のみ**。政策の当否・政党は評価しない
- 引用は原文から正確に抜粋し、原文リンクを必ず併記（一次資料で検証可能にする）
- **質問側の質も評価する**（曖昧・制度理解の誤りがあれば公平に指摘し、答弁評価で割り引く）
- 評価基準（ルーブリック・パターン分類）を公開し、全ケースに同一基準を適用する
- 質問文中の事実関係の主張（特に第三者への言及）は「質問者の主張」として明示し、
  当サイトの事実認定として扱わない

## データソース

- 参議院 質問主意書: `sangiin.go.jp/japanese/joho1/kousei/syuisyo/{回次}/`（HTML、構造が安定）
- 衆議院 質問答弁: `shugiin.go.jp/internet/itdb_shitsumon.nsf/html/shitsumon/`（同様に取得可能・未実装）
- 口頭質疑への拡張: [国会会議録検索システム API](https://kokkai.ndl.go.jp/api.html)（発言単位で取得可能）

質問主意書・答弁書は国の公文書であり、転載・引用に著作権上の支障はありません
（著作権法13条の趣旨に照らしても、公開された政府答弁の引用・分析は問題ない類型です）。

本プロジェクトの評価はAIによる試作であり、公開された質問・答弁の全文のみに
基づきます。特定の政党・議員・政府への支持・不支持を意味するものではありません。
